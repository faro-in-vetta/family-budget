# Налаштування — покроково

Один раз, хвилин на п'ятнадцять. Після цього сторінкою користуються двоє
без жодних тарифів.

---

## 1. Створити проєкт Supabase

1. Зайди на **supabase.com** → Sign up (можна через GitHub).
2. **New project**. Назва — `family-budget`.
3. **Database Password** — придумай надійний і збережи в менеджері паролів.
   Він потрібен лише для прямого доступу до бази; сторінка ним не користується.
4. **Region** — `Central EU (Frankfurt)` або `West EU (Ireland)`: ближче до Італії,
   отже швидше.
5. **Create new project** і зачекай 1–2 хвилини, поки проєкт підніметься.

## 2. Створити таблиці й правила доступу

1. Ліворуч **SQL Editor** → **New query**.
2. Відкрий файл `supabase/schema.sql`, скопіюй **весь** вміст і встав у вікно.
3. **Run**.

Має з'явитися `Success. No rows returned`. Кілька рядків `NOTICE ... skipping` —
це нормально: так виглядає повторний запуск.

Файл безпечно запускати ще раз, якщо колись доведеться.

## 3. Вимкнути зайве підтвердження пошти (за бажанням)

За замовчуванням Supabase шле лист із підтвердженням, а на безкоштовному тарифі
ліміт таких листів низький. Для двох людей простіше обійтися без них:

**Authentication** → **Sign In / Providers** → **Email** → вимкни
**Confirm email** → **Save**.

Якщо лишиш увімкненим — нічого страшного, просто після реєстрації треба буде
натиснути посилання в листі.

## 4. Взяти ключі

**Project Settings** → **API**. Потрібні два значення:

- **Project URL** — щось на кшталт `https://abcdefgh.supabase.co`
- **anon public** — довгий ключ

Ключ `service_role` з того ж екрана **нікуди не копіюй**: він дає повний доступ
повз усі правила.

## 5. Вписати ключі у сторінку

У теці `app/` зроби копію `config.example.js` з назвою **`config.js`** і встав
у неї свої значення:

```js
window.FB_CONFIG = {
  url: 'https://abcdefgh.supabase.co',
  anonKey: 'eyJhbG...довгий ключ...',
};
```

`config.js` навмисно доданий у `.gitignore` — щоб ключі не поїхали в репозиторій.
Ключ `anon` не є секретом, але звичка не класти ключі в git корисна сама по собі.

## 6. Перевірити локально

Клацни двічі на `app/index.html`. Має відкритися екран входу.

Зареєструйся, створи сім'ю — і сторінка запрацює вже по-справжньому, з базою.

## 7. Викласти в інтернет

Щоб дружина відкривала сторінку зі свого телефона, вона має лежати в мережі.
GitHub Pages — безкоштовно:

1. У репозиторії на GitHub → **Settings** → **Pages**.
2. **Source**: `Deploy from a branch`, гілка `main`, тека `/ (root)` → **Save**.
3. За хвилину сторінка буде за адресою
   `https://faro-in-vetta.github.io/family-budget/app/`.

**Важливо:** `config.js` не потрапляє в git, тож на GitHub Pages його не буде.
Або додай його в коміт свідомо (прибравши рядок із `.gitignore`), або тримай
сторінку локально. Для сімейного вжитку простіше додати: ключ `anon` публічний
за призначенням, а захист дають правила в базі, які ми перевірили окремо.

## 8. Підключити другу людину

1. Ти заходиш → **Налаштування** → там код запрошення.
2. Дружина відкриває ту саму адресу, реєструється своєю поштою,
   вводить код і своє ім'я.
3. Після цього **зміни код** кнопкою «Змінити код» — щоб той, що пройшов
   через месенджер, більше нікого не пускав.

---

## Якщо щось піде не так

**«Сторінка не налаштована»** — немає `config.js` поруч з `index.html`,
або в ньому лишились зразкові значення.

**«Невірна пошта або пароль»** — при першому вході спершу треба
зареєструватися: вкладка «Зареєструватися».

**«Пошта не підтверджена»** — або натисни посилання в листі, або вимкни
підтвердження за кроком 3.

**Сторінка довго вантажиться після тижня простою** — безкоштовний проєкт
Supabase засинає. Перше звернення його будить, далі працює нормально.

**«Змінювати дані не дозволено»** — цей учасник доданий тільки для перегляду.
